## Overview

**Plan → Work → Review → Compound → Repeat**

harnais_de_projet is a collection of agent specs and skills that implement a compound engineering workflow. It lives separate from any project repo — consuming projects reference it via their `docs/harness.md`.

### Philosophy

Each unit of engineering work should make subsequent units easier, not harder.

Traditional development accumulates technical debt — every feature adds complexity and the codebase becomes harder to work with over time. Compound engineering inverts this. 80% of effort goes to planning and review, 20% to execution:

- **Plan** thoroughly before writing code
- **Work** by following the plan, not freestyling
- **Review** to catch issues and capture learnings
- **Compound** knowledge so it's reusable

### How Consuming Projects Integrate

1. Run the onboarding process described in `harness-init.md`
2. This creates `docs/harness.md` in the consuming project, pointing back to harnais_de_projet
3. The project's `CLAUDE.md` includes: `Read docs/harness.md for agent workflow instructions`
4. Agents and skills are invoked by reading the relevant `.md` file from harnais_de_projet

See `harness-init.md` for full onboarding steps.

## Folder Structure

```
harnais_de_projet/
├── orchestrator.md           # Master prompt — runs the full Plan→Work→Review→Compound loop
├── harness-init.md           # Onboarding instructions for new projects
├── harness-template.md       # Template for consuming project's docs/harness.md
├── 01_plan/                  # Planning phase — research, brainstorm, spec out work
│   ├── PHASE.md              # Entry point for running just this phase
│   ├── agents/               # Autonomous research and analysis prompts
│   └── skills/               # Step-by-step planning processes
├── 02_work/                  # Work phase — execute plans, write code and tests
│   ├── PHASE.md
│   └── agents/
├── 03_review/                # Review phase — validate quality, catch issues
│   ├── PHASE.md
│   └── agents/
└── 04_compound/              # Compound phase — capture knowledge for reuse
    ├── PHASE.md
    └── skills/
```

### Agents vs Skills

- **Agents** are autonomous prompts designed for the Task tool. Give them a goal and they research, analyze, or validate independently.
- **Skills** are step-by-step processes with assets (templates, schemas). They guide Claude through a structured workflow with decision points.

## Consuming Project Structure

Projects that use harnais_de_projet should have the following docs structure. The `harness-init.md` onboarding process creates this automatically:

```
docs/
├── harness.md       # Points to harnais_de_projet, explains how to invoke agents
├── design-rules.md  # Visual/design rules for the project
├── to-do.md         # Priority-ordered task list (P1, P2, ...)
├── memory/          # Cross-session working memory (bug investigations, context)
├── plans/           # Feature plans generated by planning agents
├── solutions/       # Solved problems documented by compound-docs skill
└── structure/       # Repo structure documentation (architecture, components)
```

### File Descriptions

- **harness.md** — The bridge between the project and harnais_de_projet. Contains the path to the harness and instructions for invoking agents and skills.
- **design-rules.md** — Design rules for the project. Updated when visual components change.
- **to-do.md** — Loose to-do list organized by priority (P1, P2, etc.).
- **memory/** — Working memory between context windows. Used during bug investigations or multi-session tasks. After a bug is solved, the solution moves to `solutions/`.
- **plans/** — Feature plans generated by AI agents during the Plan phase.
- **solutions/** — Compounded knowledge. Solved bugs and problems are documented here for future agents to reference.
- **structure/** — Documents the repo's structure at the project, component, and feature level.
